# Browser OHTTP wallet proof — Continuation 02

**Result: 22 checks passed on Chromium 156.0.8078.4 and Zcash testnet.** The pinned WebZjs candidate encrypted RPCs in the browser, including in its dedicated sync workers. The path was browser → local relay → local gateway → local gRPC-web proxy → testnet over verified TLS.

- Fresh direct and OHTTP scans matched at block **4,606,479**: the same block hash, confirmed **0.1 TAZ** Ironwood receipt, balance and history. A separate browser OHTTP transaction lookup matched the direct backend response.
- The wallet sent **0.01 TAZ** once through OHTTP. The backend accepted it, and the original transaction ID was mined at **4,606,481**. Both disposable wallets showed the confirmed transfer.
- A real 100-block stream delivered data before terminal authentication. Cancellation, relay interruption, invalid keys, nonzero final RPC status, and missing or corrupted OHTTP endings were checked. The funded run recorded **70 relay requests and zero attempted direct bypasses** in OHTTP mode. The gateway did not receive the probe's client identity markers.

Some links in the historical baseline README therefore refer to files outside this ZIP. The build needs the pinned toolchain and network dependency access; the live workflow also needs a responding testnet backend and faucet. New runs will have different heights and transaction IDs. The archive excludes private keys, wallet stores, browser profiles and credentials.
